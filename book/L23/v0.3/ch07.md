### 7.1 核心概念與技術原理

<!-- pdf-page 62 -->
#### 7.1.1 前處理的正確順序
核心必考
1.切分資料集——必須最先做。
2.探索性分析。
3.缺失值處理 →離群值處理 →類別編碼 →特徵縮放。
4.特徵工程（交互項、時間特徵、彙總統計、領域衍生）。
5.不平衡處理——僅對訓練集。
鐵律：先切分，後轉換
所有需要「學習參數」的前處理——標準化的 µ與 σ、插補的中位數、One-Hot的類別清單、目標
編碼的分組均值、重採樣合成的樣本——都只能用訓練集計算，再套用到驗證與測試集。
實作上以管線封裝可自動避免此錯誤：交叉驗證時會在每一折的訓練部分內重新擬合各個轉換器。

<!-- pdf-page 62 -->
#### 7.1.2 類別編碼選型
核心必考
| 編碼 | 常見適用情境 | 風險與限制 |
|---|---|---|
| One-Hot | 無序、基數較低的類別 | 高基數會造成高維稀疏特徵；沒有通用的 15 類門檻 |
| 順序編碼 | 有序類別，如低／中／高 | 用於無序類別可能讓模型誤認有大小關係 |
| 目標編碼 | 郵遞區號等高基數類別 | 必須在訓練折內估計並避免本列目標直接洩漏；可考慮平滑或折外編碼 |
| 頻率編碼 | 類別出現頻率可能有訊息 | 不同類別的頻率相同時無法區分 |
| 嵌入 | 深度模型處理高基數類別 | 需足夠資料學習，並處理未見過的類別 |
未知類別
上線後出現訓練時未見過的類別值時，One-Hot編碼器會報錯或產生全零向量。須事先設定忽略未
知類別，或在訓練前先把低頻類別合併為「其他」桶。

#### 7.1.3 哪些模型需要縮放
核心必考
| 模型 | 縮放需求 | 原因 |
|---|---|---|
| KNN、SVM、K-Means、PCA | 通常需要 | 距離或變異量易受特徵尺度影響 |
| 線性／邏輯斯迴歸，尤其含正則化時 | 通常有幫助 | 改善數值收斂，使正則化懲罰較可比 |
| 神經網路 | 通常有幫助 | 常有助於梯度穩定及收斂 |
| 決策樹、隨機森林、梯度提升樹 | 通常不需要 | 閾值切分主要取決於特徵排序 |

#### 7.1.4 特徵工程與資料增強
官方補充
常見手法：交互項（兩特徵相乘或相除）、多項式項、時間特徵（週期性以正弦餘弦編碼）、分組彙總
統計、領域衍生（如負債收入比）。
資料增強必須符合物理意義
對 X光片做水平翻轉會製造出現實中極罕見的鏡像解剖結構；對含文字的影像做垂直翻轉會生成無
效樣本；對「方向具意義」的瑕疵做旋轉會改變標籤語意。
增強必須通過「這個增強後的樣本在現實中可能出現嗎」的檢驗。

#### 7.1.5 考點補丁：偏態特徵的對數轉換何時有害
核心必考

- **對數轉換的用途**：把**右偏**（長尾在右）的分布壓縮成接近對稱，穩定變異數，讓線性模型與距離度量更合理。常用於所得、金額、人口、停留時間。
- **什麼時候有害（本補丁的重點）**：

  | 情況 | 為什麼有害 |
  |---|---|
  | **含 0 或負值** | log(0) 未定義、log(負) 無實數解。須先加常數（log1p）或改用其他轉換 |
  | **左偏分布** | 對數轉換會**加劇**左偏，方向相反 |
  | **分布本來就接近對稱** | 轉換後反而製造偏態，且損失可解釋性 |
  | **需要解釋原始尺度的係數** | 對數轉換後係數不再是「每增加一單位」的效果：只取 X 的對數時，係數表示 X 增加 1% 時 Y 約變動係數 ÷ 100；X、Y 都取對數時，係數才是「彈性」 |
  | **要做樹模型** | 樹模型只依賴**排序**，單調轉換**不改變分裂結果**，做了等於白做 |
  | **極端值本身就是訊號** | 對數壓縮會讓異常的大值不再突出，偵測不到異常 |

- **一句判斷規則**：題幹出現「特徵右偏嚴重」→ 可考慮對數轉換；出現「特徵含 0」「要做樹模型」「需要解釋每單位變動的效果」→ **不該**用對數轉換。
- **樹模型與單調轉換（最常考的推論）**：決策樹、隨機森林、梯度提升樹的分裂只比較大小順序。**任何單調遞增轉換（對數、平方根、Box-Cox）都不改變樹的結構與預測結果**。因此對樹模型做對數轉換只影響計算效率，不影響效能。
- **替代方案**：
  - **Box-Cox 轉換**：以 λ 參數自動搜尋最佳冪次（要求正值）。
  - **Yeo-Johnson 轉換**：可處理 0 與負值。
  - **分位數轉換**：強制映射到指定分布（如常態），但會失去部分原始資訊且不易解釋。
  - **穩健縮放（RobustScaler）**：以中位數與 IQR 縮放，不改變分布形狀但降低離群值影響。
- **易混點**：**標準化（standardization）不會改變分布形狀**，只改變位置與尺度；**對數轉換會改變形狀**。兩者常被混為一談，但解決的是不同問題——標準化是為了讓梯度下降與距離度量正常工作，對數轉換是為了修正偏態。
- **對應題號**：115-1 L23 Q25（正解 A，題幹＋正解）。

#### 7.1.6 考點補丁：滑動窗口與滯後特徵
核心必考

- **定義**：
  - **滯後特徵（lag feature）**：把時間序列**往前平移**當作特徵，例如用 t−1、t−2、t−3 的值預測 t 的值。
  - **滑動窗口（rolling window）**：對過去 w 期的資料計算統計量（平均、標準差、最大、最小）當作特徵，例如「過去 7 天的平均銷售量」。
- **一句判斷規則**：題幹出現「用過去的資料預測未來」「要捕捉趨勢與季節性」→ 滯後特徵與滑動窗口；出現「特徵裡含未來資訊」→ **資料洩漏**，是時序建模最嚴重的錯誤。
- **時間點正確性（point-in-time correctness）是核心原則**：任何在預測時刻 t **還不知道**的資訊都不能進特徵。三個常見洩漏：
  1. **用了中心滑動窗口**（`center=True`）：窗口包含未來。
  2. **用了全期間的統計量做標準化**（例如用整份資料的平均與標準差）——必須只用訓練期或滾動歷史。
  3. **標籤的時間對齊錯誤**：預測 t 的目標卻用了 t 當期才知道的特徵。
- **驗證方式**：本節以過去預測未來的任務，應用**時間切分**（前段訓練、後段測試）或**前向滾動驗證（walk-forward validation）**。隨機切分可能讓訓練集含有驗證期之後的資訊，使離線指標偏樂觀或不符合上線情境。
- **易混點**：
  - **滑動窗口與滯後特徵不同**。滯後是「取特定延遲的值」，窗口是「對一段期間做彙總」。
  - **窗口長度是超參數**。太短則噪音大，太長則反應遲鈍且樣本需求增加。
  - **滾動統計量會產生前段缺失值**（前 w−1 期無完整窗口），須明確處理而非填 0。
  - **差分與滯後不同**：一階差分（t 減 t−1）常用於去除趨勢；季節性可能需要按季節週期差分。滯後則是保留歷史值當特徵。
- **對應題號**：115-1 L23 Q26（正解 D，題幹＋正解）。

#### 7.1.7 學習指引補充：Box-Cox 轉換與遞迴特徵消除
官方補充

- **Box-Cox 轉換**：y(λ) = (y^λ − 1) ÷ λ（λ ≠ 0），λ = 0 時為 ln y，λ 由資料估計；可把右偏且變異數隨平均增大的變數拉回較對稱。前提是 y **大於 0**，含 0 或負值時改用 Yeo-Johnson 轉換。
- **遞迴特徵消除（RFE）**：訓練模型 → 依係數或特徵重要性移除最不重要的特徵 → 重新訓練，重複到剩下指定數量；RFECV 以交叉驗證決定保留幾個特徵。屬於包裹式（wrapper）方法，效果通常較好，但成本較高。
- **一句判斷規則**：「目標變數右偏、殘差變異不固定」→ 對目標做 Box-Cox 或對數轉換；「依模型表現逐步刪除特徵」→ RFE。
- **易混點**：RFE 必須只在訓練資料或交叉驗證的每一折內執行，否則屬特徵篩選洩漏（見 7.1.1）；滯後特徵見 7.1.6。
- **指引頁碼**：學習指引科目三 5-3、5-5、5-7、5-10。

### 7.2 程式判讀重點
核心必考
正確與錯誤的前處理寫法

```python
# 錯誤：先對全部資料標準化再切分 ->測試集統計資訊洩漏
X_scaled= StandardScaler().fit_transform(X)
X_tr,X_te = train_test_split(X_scaled)
# 正確：以 Pipeline封裝，交叉驗證時每一折內重新擬合
pipe= make_pipeline(StandardScaler(), LogisticRegression())
scores= cross_val_score(pipe, X, y, cv=5)
```

fit / transform / fit_transform

```python
scaler= StandardScaler()
X_tr_s= scaler.fit_transform(X_tr)#學習mu、sigma並轉換
X_te_s= scaler.transform(X_te)#只轉換，沿用訓練集的mu、sigma
X_te_bad= scaler.fit_transform(X_te)#洩漏：用測試集自身統計量
```

必考：對測試集呼叫fit_transform是資料洩漏的典型錯誤，且會使訓練與測試的尺度不一致。

#### 7.2.1 考點補丁：以 NumPy 手動標準化
核心必考

- **定義**：不用 `StandardScaler` 時，Z-score 標準化可以用兩行 NumPy 完成。`axis=0` 表示沿著列方向計算，得到**每個欄位（特徵）**各自的平均與標準差。

  ```python
  mu = X_train.mean(axis=0)
  sd = X_train.std(axis=0)
  X_train = (X_train - mu) / sd
  X_test = (X_test - mu) / sd   # 測試集沿用訓練集的 mu 與 sd
  ```

- **一句判斷規則**：減平均使每個特徵的平均變成 **0**；除以標準差使標準差變成 **1**。結果**沒有**固定範圍，壓到 0 到 1 之間的是 Min-Max 正規化。
- **為什麼神經網路要標準化**：各特徵尺度一致時，梯度在各方向上的大小相近，訓練較穩定，也較不容易出現梯度爆炸或消失。
- **易混點**：
  - 標準化屬於**特徵縮放**，不是特徵選擇；它不會刪掉任何欄位。
  - 測試集必須用**訓練集**算出的平均與標準差；用測試集自己的統計量會造成洩漏（見 7.2 前段）。
  - `X.std(axis=0)` 本身只是算出標準差，不會把資料變成標準化後的值。
- **對應題號**：114-2 L23 Q48（正解 C，程式圖）。

#### 7.2.2 考點補丁：影像像素縮放與標籤的獨熱編碼
核心必考

- **像素縮放**：8 位元影像的像素值範圍是 0～255。把每個像素除以 255.0，範圍變成 **0～1**，這是用已知範圍做的 Min-Max 縮放，**不是** Z-score 標準化（平均不會是 0、標準差不會是 1）。因為 255 是固定常數，不從資料學參數，訓練集與測試集直接各自除以 255 不會造成洩漏。
- **為什麼要縮放**：輸入尺度一致且不大時，梯度大小較穩定，較不易出現梯度爆炸或消失，訓練收斂較快，也較容易得到泛化良好的模型。
- **標籤獨熱編碼**：`tf.keras.utils.to_categorical(y, num_classes)` 把整數類別（如 3）轉成長度為類別數的 0／1 向量（如 `[0,0,0,1,0,…]`），配合輸出層 **softmax** 與 `categorical_crossentropy`。若標籤保持整數，改用 `sparse_categorical_crossentropy`，不需要先做獨熱編碼。

  ```python
  x_tr, x_te = x_tr / 255.0, x_te / 255.0              # 像素縮放到 0~1
  y_tr = tf.keras.utils.to_categorical(y_tr, 5)         # 5 類 -> 獨熱向量
  ```

- **一句判斷規則**：看到「÷ 255」→ 範圍 0～1 的縮放；看到 `to_categorical` → 標籤變成獨熱向量，輸出層用 softmax。
- **易混點**：獨熱編碼的是**標籤 y**，不是影像 x；除以 255 不會把範圍壓到 0～31 或其他區間。
- **對應題號**：115-1 L23 Q46（正解 B，程式圖）。

### 7.3 常見陷阱與錯誤觀念
• 在切分前做任何會學習參數的轉換。
• 對測試集fit_transform。
• 目標編碼未做折外計算。標籤資訊直接洩漏至特徵。
• 對無序類別用順序編碼。製造不存在的大小關係。
• 未處理未知類別。上線即報錯。
• 對樹模型做縮放。無害但多餘。
• 資料增強違反物理意義。
• 以 0填補數值型缺值。0通常是合法值。

#### 模擬題 SIM-L23301-001

模擬題 SIM-L23301-001 ｜ 程式判讀 ｜ 難度：中級 ｜ 對應 L23301
下列程式的問題為何？

```python
scaler= StandardScaler()
X_train_s= scaler.fit_transform(X_train)
X_test_s= scaler.fit_transform(X_test)
model.fit(X_train_s,y_train)
```

(A)沒有問題，兩個資料集各自標準化較為公平
(B)第三行對測試集重新fit，使用了測試集自身的統計量，屬資料洩漏且造成訓練與測試的尺度不
一致；應改為scaler.transform(X_test)
(C)應改用MinMaxScaler即可避免
(D)應先對合併後的完整資料fit，以保持一致
答案與逐項解析
答案：B
(A) ×「各自標準化」正是錯誤所在——同一個原始數值在訓練集與測試集會被映射成不同的縮放值，
模型學到的關係在測試時失效。
(B)✓正解。轉換器必須fit於訓練集、transform於測試集，確保兩邊套用同一組 µ與 σ。
(C) ×換一種縮放器不改變「對測試集重新 fit」這個錯誤本質。
(D) ×對合併資料fit雖能保持尺度一致，但統計量納入了測試集資訊，同樣構成資料洩漏，是更
隱蔽的錯誤。
干擾項設計理由：(D)是最具吸引力的誘答——它確實解決了「不一致」，卻引入更嚴重的洩漏。
延伸考點：以make_pipeline(StandardScaler(), Model())封裝後交給cross_val_score，可讓 scaler
在每一折的訓練部分內重新擬合，從結構上杜絕此類錯誤。

#### 模擬題 SIM-L23301-002

模擬題 SIM-L23301-002 ｜ 選型題 ｜ 難度：中級 ｜ 對應 L23301
某資料集含「郵遞區號」欄位，共 3,000個相異值。若使用線性模型，下列編碼方式何者最為適當？
(A) One-Hot編碼，產生 3,000個二元欄位
(B)順序編碼，依郵遞區號數值大小排序
(C)折外目標編碼（僅於訓練折內計算分組統計並加平滑），或合併為較粗的區域層級
(D)直接刪除該欄位
答案與逐項解析
答案：C
(A) × 3,000個相異值會製造 3,000個極稀疏的欄位，維度爆炸且多數欄位樣本數極少，線性模型難
以穩定估計係數。
(B) ×郵遞區號是無序類別，數值大小沒有實質意義。順序編碼會讓模型誤以為「郵遞區號 800比
100大 8倍」，學到錯誤關係。
(C)✓正解。高基數類別的標準處理有兩條路：目標編碼（須折外計算並加平滑以避免目標洩漏），
或依業務意義合併為較粗的層級（如縣市）。
(D) ×郵遞區號常帶有重要的地域資訊（消費力、風險），直接刪除損失過大。
干擾項設計理由：(B)是實務上很常見的偷懶作法，也是最容易產生隱蔽錯誤的選項。
延伸考點：目標編碼的洩漏風險極高——若直接用全體資料計算各郵遞區號的目標均值，該均值已
包含該樣本自身的標籤。正確作法是折外編碼：計算某折的編碼時只使用其他折的資料，並對樣本
數少的類別加平滑（往全域均值收縮）。另須注意郵遞區號可能是代理變數，涉及公平性議題（見
Chapter12）。

#### 模擬題 SIM-L23301-003

模擬題 SIM-L23301-003 ｜ 觀念題（反向） ｜ 難度：基礎 ｜ 對應 L23301
下列哪一種模型不需要對特徵進行縮放？
(A) K近鄰演算法
(B)支援向量機
(C)梯度提升樹
(D)具 L2正則化之邏輯斯迴歸
答案與逐項解析
答案：C
(A) ×（需要）以距離計算鄰居，尺度大的特徵主宰距離。
(B) ×（需要）以間隔與核函數計算，對尺度敏感。
(C)✓正解（不需要）。樹模型依特徵閾值切分，任何單調變換都不改變切點的相對順序，因此縮放
不影響結果。
(D) ×（需要）正則化懲罰對係數大小敏感，未縮放會使不同尺度的特徵受到不公平的懲罰。
延伸考點：樹模型通常不需特徵縮放；距離型與正則化線性模型多半需要，神經網路也常因縮放而更易訓練。不能用「只有樹模型不需要」作絕對判斷。
另注意 PCA 在特徵單位或尺度不同時通常應先標準化，避免大尺度變數主宰主成分；同單位資料至少要中心化。

#### 模擬題 SIM-L23301-004

模擬題 SIM-L23301-004 ｜ 程式判讀 ｜ 難度：中級 ｜ 對應 L23301
模型上線後，遇到訓練時未出現過的類別值即拋出錯誤。下列處置何者最為適當？
(A)每次遇到新類別就重新訓練整個模型
(B)設定編碼器忽略未知類別（產生全零向量），或在訓練前先將低頻類別合併為「其他」桶
(C)上線前手動列舉所有可能的類別值
(D)改用順序編碼即可避免此問題
答案與逐項解析
答案：B
(A) ×不可行——新類別隨時可能出現（新商品、新分行、新裝置型號），每次重訓成本過高且服務
會中斷。
(B)✓正解。兩種標準作法：讓編碼器對未知類別輸出全零（模型視為「無此類別資訊」），或在訓練
階段就把低頻類別合併為「其他」桶，使上線後的新類別自然落入該桶。
(C) ×對高基數且持續成長的類別（商品編號、郵遞區號）不可能窮舉。
(D) ×順序編碼同樣會遇到未知值的問題，且對無序類別會引入錯誤的大小關係。
干擾項設計理由：(C)看似「完整」，但在真實系統中不可維護。
延伸考點：這屬於訓練與服務偏斜的一種——訓練環境的假設在生產環境不成立。同類問題還包括：
欄位型別變更、單位變更、上游系統改版。因應之道是在推論管線加入輸入結構驗證，發現異常即
告警並走降級路徑。

#### 模擬題 SIM-L23301-005

模擬題 SIM-L23301-005 ｜ 情境題 ｜ 難度：中級 ｜ 對應 L23301
某團隊欲以資料增強擴充胸部 X光片訓練集。下列增強方式何者最不適當？
(A)小幅度旋轉（±10度）
(B)亮度與對比度微調
(C)水平翻轉
(D)隨機裁切後縮放回原尺寸
答案與逐項解析
答案：C
(A)✓（適當）病人擺位本來就有小幅角度差異，符合現實。
(B)✓（適當）不同機器與曝光參數確實會造成亮度差異。
(C) ×最不適當（即為答案）。人體胸腔是左右不對稱的——心臟偏左、肝臟偏右。水平翻轉會製造
出現實中極罕見的鏡像解剖結構，模型可能因此學到錯誤的空間先驗，甚至在判讀真實的鏡像
異位病例時反而失準。
(D)✓（適當）模擬取像範圍的差異，屬合理變異。
干擾項設計理由：水平翻轉是自然影像（貓狗、車輛）最常用的增強手段，考生容易直覺套用而忽略
醫療影像的解剖不對稱性。
延伸考點：資料增強的檢驗標準是「增強後的樣本在現實中可能出現嗎」。其他反例：對含文字的影
像做翻轉、對「方向即標籤」的瑕疵做旋轉、對時序資料做隨機打亂。增強必須保持標籤語意不變。

#### 模擬題 SIM-L23301-006

模擬題 SIM-L23301-006 ｜ 觀念題 ｜ 難度：中級 ｜ 對應 L23301
某資料集的「年收入」欄位缺失率為 22%，且分析顯示高收入者較不願填答。下列處置何者最為適
當？
(A)以觀測到的平均收入填補所有缺失值
(B)屬非隨機缺失，簡單插補會系統性低估；應保留缺失指示欄、採適當插補方法，並於報告中揭
露偏誤風險
(C)刪除所有含缺失的列
(D)以 0填補
答案與逐項解析
答案：B
(A) ×觀測值本身已偏向中低收入，以其平均填補會使整體分布更向中低集中，偏誤加劇。
(B)✓正解。「高收入者不填」代表缺失與該欄未觀測到的值本身相關（非隨機缺失）。此時任何僅依
觀測值推估的方法都會低估，故須保留指示欄並明確揭露偏誤。
(C) ×刪除 22%的資料且系統性移除高收入群體，樣本代表性嚴重受損。
(D) ×「未填答」與「收入為 0」是完全不同的事，會製造大量假的零收入樣本。
延伸考點：三種缺失機制的判別關鍵——與任何變數都無關為完全隨機缺失；與其他已觀測變數有關
為隨機缺失（可用模型插補）；與該欄自身未觀測值有關為非隨機缺失（無法僅靠資料修正）。缺失指
示欄本身常是有用特徵——「不願填答」這個行為就帶有資訊。
