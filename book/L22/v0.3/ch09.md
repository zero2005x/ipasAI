### 9.1 核心概念與技術原理

<!-- pdf-page 80 -->
#### 9.1.1 圖表選型對照
核心必考
| 分析目的 | 常用圖表 | 常見誤用 |
|---|---|---|
| 比較類別大小 | 長條圖；長標籤可用橫向 | 類別太多時用圓餅圖，難比較相近比例 |
| 呈現趨勢 | 折線圖 | 用不連續或不等間隔時間點卻未標示清楚 |
| 呈現分布 | 直方圖、箱型圖、小提琴圖 | 只報平均數，隱藏分布與離群點 |
| 兩變數關係 | 散布圖，可加趨勢線 | 只報相關係數而不檢查形狀與離群點 |
| 組成比例 | 堆疊或 100% 堆疊長條圖 | 層數過多，難比較中間區塊 |
| 地理分布 | 面量圖 | 比較人口規模不同地區時只呈現絕對數 |
| 關聯矩陣 | 熱力圖 | 色階不當或未標示數值範圍 |

#### 9.1.2 視覺化的誠信原則
核心必考
五條必記規則
1.長條圖的 Y軸必須從 0起。截斷軸會誇大差異，是最常見的誤導手法。折線圖為呈現變化細
節可不從 0起，但須明確標示。
2.雙 Y軸容易製造假關聯，應謹慎使用並標明各自單位。
3.避免 3D效果，透視會扭曲面積與長度的感知。
4.色彩可及性：約 8%男性有紅綠色覺辨識障礙，關鍵資訊不應僅以紅綠對比傳達，須輔以形狀
或標籤。
5.資料墨水比：刪除無資訊的格線、陰影與裝飾，讓版面留給資料本身。

**長尾金額的尺度選擇**：若消費金額跨越數個數量級，原尺度箱型圖可能把多數資料擠在狹小區間；可另畫明確標示的對數刻度箱型圖，並視分群目的搭配各消費層級的分布圖。對數刻度的等距代表**相同比例**，會壓縮高金額之間的絕對差額，並非把高金額的絕對差異放大。資料含 0 或負值時不能直接套用一般對數軸，應先處理或選用其他尺度。對應 114-2 L22 Q25 的官方答案 A；該選項「放大高金額變化差異」是試題措辭，讀圖時須依上述尺度性質判斷。參見 [Matplotlib 對數尺度範例](https://matplotlib.org/stable/gallery/scales/log_demo.html)。

#### 9.1.3 大規模視覺化效能
核心必考
核心問題是不能把上億筆點全部畫出來——瀏覽器會當掉，且過度重疊的散布圖本身也無法閱讀。
| 策略 | 作法 | 備註 |
|---|---|---|
| 伺服器端預彙總 | 先彙總到展示所需粒度再回傳 | 減少傳輸量與瀏覽器負擔 |
| 抽樣 | 隨機或分層抽樣後繪製 | 應確認抽樣能代表關心的群體 |
| 分箱 | 例如以六角形分箱呈現點的密度 | 適合點數多且重疊嚴重的散布圖 |
| 資料立方體／物化視圖 | 預先計算常用維度組合 | 加速互動式鑽取，但需維護與更新 |
| 前端虛擬捲動 | 只渲染可視範圍 | 適用大型表格，不能取代後端分頁或查詢優化 |
儀表板設計應遵循「先總覽、再縮放與篩選、最後細節按需」的順序。

#### 9.1.4 考點補丁：Tufte 的資料密度原則
核心必考

- **定義**：Edward Tufte 提出的**資料密度（Data Density）** 是「圖中呈現的資料項數 ÷ 圖表面積」。原則是在可讀的前提下，讓有限版面承載**盡可能多的有效資料**。同一脈絡的原則還有**資料墨水比**（見 9.1.2）與**小倍數圖**（small multiples，同尺度的小圖並排）。
- **一句判斷規則**：選項同時做到「單一版面整合多組資料」、「比例一致」與「標示清楚」→ 符合資料密度。把資料拆成很多張圖、只列表格，或堆滿裝飾，都不符合。
- **易混點**：
  - **提高資料墨水比不等於刪光所有標示**。軸標籤、圖例與必要格線是讀懂資料所需，屬於資料的一部分；該刪的是陰影、3D、裝飾色塊等**圖表垃圾（chartjunk）**。
  - 分散到多張圖「避免資訊過載」，與資料密度原則方向相反；若真的需要分圖，應採**同尺度**的小倍數圖，讓讀者可直接比較。
  - 表格數值精確，但無法讓主管快速看出趨勢；呈現趨勢仍以圖為主。
- **對應題號**：114-2 L22 Q21（正解 B）、115-1 L22 Q27（正解 D）。

### 9.2 程式判讀重點
核心必考
座標軸設定與誤導

```python
ax.bar(x,y)
ax.set_ylim(95,100)#危險：長條圖截斷Y軸，視覺上誇大微小差異
ax.set_ylim(bottom=0)#長條圖的正確作法
```

必考：`set_ylim` 若用於以長度比較絕對數值的長條圖並將下界設為非 0，即構成截斷軸。若另對**正值資料**採用對數尺度，應改選適合讀取比例的圖形並清楚標示刻度；對數軸不含 0，不能把上面 `set_ylim(bottom=0)` 的線性長條圖寫法直接接在對數軸之後。對數軸上等距的刻度代表倍數而非差額。

#### 9.2.1 考點補丁：pandas 與 seaborn 繪圖語法
核心必考

- **定義**：常考的繪圖題都是「先把資料整理成正確形狀，再選對函式」。pandas 的 `.plot()` 直接畫已彙總的 Series；seaborn 的 `barplot` 預設會對每個類別計算**平均**並畫出信賴區間，`countplot` 則只**計數**。
- **一句判斷規則**：要「各類別的總額」→ 先 `groupby(...).sum()` 再畫，或在 `sns.barplot` 設 `estimator=sum`；要「各類別出現幾次」→ `countplot` 或 `value_counts()`；要「前 N 名」→ 先 `nlargest(N, 欄)` 再畫。
- **寬表轉長表**：好幾個欄位要並排成長條時，先用 `pd.melt` 把「欄名」變成一欄 `variable`、「值」變成一欄 `value`，seaborn 才能以 `x="variable", y="value"` 繪圖。
- **程式範例**：

  ```python
  sales.groupby("store")["amount"].sum().plot(kind="bar")      # 各店總額
  long = pd.melt(sales, value_vars=["q1", "q2", "q3", "q4"])
  sns.barplot(x="variable", y="value", data=long, estimator=sum)  # 各季總額
  sns.barplot(x="item", y="amount", data=sales.nlargest(5, "amount"))  # 前五名
  ```

- **易混點**：
  - `groupby(...).count()` 算的是筆數，`.mean()` 是平均，都不是總額。
  - `data.head(5)` 取的是**前 5 列**，不是數值最大的 5 筆。
  - `lineplot` 用在有順序的連續軸（時間）；類別比較用長條圖（見 9.1.1）。
- **對應題號**：114-2 L22 Q45（正解 A）、114-2 L22 Q46（正解 C）、114-2 L22 Q47（正解 B）。

### 9.3 常見陷阱與錯誤觀念
• 長條圖截斷 Y軸。最經典的誤導。
• 圓餅圖塞入十幾個類別。人眼無法比較相近的扇形角度。
• 以絕對數繪製地圖。人口多的區域通常數字較大，須先標準化為每萬人比率。
• 只呈現平均數。兩組平均相同但分布完全不同的情況極常見，須搭配箱型圖或直方圖。
• 對數尺度未標示。讀者會把倍數差異誤讀為差額。
• 把上億筆原始點直接送到前端。應在伺服器端先彙總。
• 僅以紅綠區分好壞。色覺辨識障礙者無法判讀。

視覺化在 AI治理中的角色常被低估，但它是透明性原則的主要載體。
•金管會指引就透明性與可解釋性有所要求（屬主管機關期待），實務上模型監控儀表板（效能趨勢、漂移
指標、分群公平性差距）即為向稽核與管理層說明模型狀態的標準工具。
•公平性視覺化應以分群並列呈現各群體的核准率與誤判率，而非只呈現整體平均——整體良好而某一子群
顯著較差，正是彙總數字所掩蓋的問題。
•對外揭露時不得以圖表誤導。截斷軸誇大模型改善幅度、只呈現有利期間的效能曲線，均可能構成不實陳
述。
•編者提醒：呈現含個資的分析結果時，應避免小樣本格造成的再識別風險——某圖表格中僅 1至 2人時可
反推個體。實務常設定最小顯示門檻（如樣本數低於某值即不顯示或合併）。

#### 模擬題 SIM-L22303-001

模擬題 SIM-L22303-001 ｜ 選型題 ｜ 難度：基礎 ｜ 對應 L22303
某團隊欲比較 12個產品線的年度營收占比。下列圖表何者最為適當？
(A)圓餅圖，因其最能表達「占比」概念
(B)橫向長條圖（依數值排序），必要時輔以百分比標籤
(C) 3D立體圓餅圖，視覺效果較佳
(D)折線圖
答案與逐項解析
答案：B
(A) ×圓餅圖在類別超過約 5個時，相近的扇形角度人眼難以區分；12個類別會使圖形完全無法閱
讀。
(B)✓正解。長條圖以長度編碼數值，是人眼最精確的視覺通道；橫向排列可容納較長的產品線名
稱；依數值排序讓比較更容易。加上百分比標籤即可同時傳達占比。
(C) × 3D透視會扭曲面積感知，前方扇形看起來比實際大，屬應避免的效果。
(D) ×折線圖用於呈現連續變化（如時間趨勢），把類別用線連起來會暗示不存在的順序關係。
干擾項設計理由：(A)利用「占比＝圓餅圖」的直覺聯想，是最常見的圖表誤用。
延伸考點：若同時要看「12個產品線」與「跨 3年變化」，應改用分組長條圖或小型多重圖，而非把
36個資料點塞進單一圓餅或堆疊圖。

#### 模擬題 SIM-L22303-002

模擬題 SIM-L22303-002 ｜ 程式判讀 ｜ 難度：中級 ｜ 對應 L22303
下列程式繪製各分行的客戶滿意度（滿分 100，實際值介於 96至 98之間）。其主要問題為何？

```python
ax.bar(branches,scores)
ax.set_ylim(95.5,98.5)
```

(A)沒有問題，縮小範圍可看清細微差異
(B)長條圖截斷 Y軸會使 96與 98的差距在視覺上被放大數倍，構成誤導；長條圖應從 0起，若需
強調細微差異應改用點圖或明確標示截斷
(C)應改用set_xlim
(D)應加上set_yscale('log')即可解決
答案與逐項解析
答案：B
(A) ×「看清細微差異」的需求是合理的，但用長條圖搭配截斷軸是錯誤手段——長條圖以長度編碼
數值，截斷後長度比例不再等於數值比例。
(B)✓正解。96與 98的實際差距是 2分（約 2%），但在 95.5至 98.5的軸上，長條長度差距可達數
倍，嚴重誇大。若確實要強調細微差異，應改用點圖（以位置而非長度編碼）或明確標示軸已截
斷。
(C) × X軸是類別軸，與此問題無關。
(D) ×對數尺度用於處理跨數量級的資料；本例數值範圍極窄，取對數毫無幫助，反而更難解讀。
干擾項設計理由：(A)提出了一個真實存在的分析需求，測試考生能否區分「需求合理」與「手段正
確」。
延伸考點：編碼通道的精確度排序大致為：位置 >長度 >角度 >面積 >顏色深淺。這解釋了為何
長條圖優於圓餅圖，也解釋了為何強調細微差異時點圖（位置編碼）比截斷的長條圖更誠實。

#### 模擬題 SIM-L22303-003

模擬題 SIM-L22303-003 ｜ 情境題 ｜ 難度：中級 ｜ 對應 L22303
某分析師需在儀表板中呈現 2億筆交易的「金額與交易時長」關係。直接繪製散布圖導致瀏覽器停
止回應。下列處置何者最為適當？
(A)提高前端機器規格，即可繪製完整散布圖
(B)在伺服器端先以六角形分箱彙總密度，或採分層抽樣後繪製，並提供鑽取查看細節
(C)隨機刪除 99%的資料後直接繪製，不需說明
(D)改用長條圖呈現
答案與逐項解析
答案：B
(A) ×這是架構問題而非硬體問題。即使能畫出來，2億個重疊的點也無法閱讀——過度繪製會讓密
集區變成一團實心色塊。
(B)✓正解。分箱在保留密度資訊的同時大幅降低繪製元素數量；分層抽樣則確保各區間都有代表
性。搭配鑽取可在需要時查看明細，符合「先總覽、再篩選、最後細節」的原則。
(C) ×隨機抽樣本身可行，但不說明即構成資訊揭露不足；且對稀有但重要的高額交易，簡單隨機
抽樣容易全部漏掉，應採分層抽樣。
(D) ×長條圖無法表達兩個連續變數之間的關係。
延伸考點：大規模視覺化的核心思維是把運算留在資料端——傳到前端的應該是彙總後的少量資料，
而非原始明細。這與 Chapter5的欄式儲存、述詞下推是同一套邏輯。

#### 模擬題 SIM-L22303-004

模擬題 SIM-L22303-004 ｜ 治理題 ｜ 難度：中級 ｜ 對應 L22303
某銀行的模型監控儀表板呈現「整體核准率」與「整體誤判率」兩條趨勢線，數值皆穩定良好。稽核
人員認為此呈現不足以支持公平性宣稱。下列理由何者最為適當？
(A)應改用 3D圖表以增加資訊量
(B)整體平均會掩蓋子群差異；公平性檢視應以各群體並列呈現核准率與誤判率，並揭露群間差距
(C)應將 Y軸截斷以放大變化，讓趨勢更明顯
(D)應只呈現表現最佳的季度，以增強說服力
答案與逐項解析
答案：B
(A) × 3D效果扭曲感知，且不解決「缺少分群資訊」的核心問題。
(B)✓正解。整體良好而某一子群顯著較差，正是彙總數字所掩蓋的典型問題。公平性檢視必須分
群並列。
(C) ×截斷軸屬誤導手法，在對稽核揭露的場景中尤其不當。
(D) ×只呈現有利期間屬選擇性揭露，可能構成不實陳述。
干擾項設計理由：(C)(D)兩者都是「讓數字更好看」的手法，正是治理場景中應被明確禁止者。
延伸考點：分群呈現時須留意小樣本格的再識別風險——某子群僅數人時，公開其核准率可能反推個
體。實務上設定最小顯示門檻或合併相近群組。此議題與 L22404的去識別化相通。
