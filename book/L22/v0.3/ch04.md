### 4.1 核心概念與技術原理

#### 4.1.1 資料品質六構面
核心必考
| 構面 | 定義 | 自動檢核示例 |
|---|---|---|
| 完整性 | 必填資料是否齊全 | 各欄缺失率與門檻告警 |
| 正確性 | 資料是否反映真實或權威來源 | 對照權威來源或業務規則 |
| 一致性 | 跨系統資料是否互相矛盾 | 比對主檔與交易檔 |
| 時效性 | 資料是否足夠新 | 比較最新時間戳與使用時間 |
| 唯一性 | 不應重複的紀錄是否重複 | 主鍵唯一性檢查 |
| 有效性 | 是否符合格式與值域 | 型別、範圍、正規表示式檢查 |
品質檢核應自動化並納入管線，於每次批次執行時產生報告，而非人工抽查。

<!-- pdf-page 36 -->
#### 4.1.2 三種缺失機制
核心必考
| 機制 | 定義 | 處置考量 |
| --- | --- | --- |
| MCAR：完全隨機缺失 | 缺失與已觀測及未觀測變數皆無關 | 刪除完整案例在適當條件下不致引入系統性偏誤，但會損失樣本與檢定力 |
| MAR：隨機缺失 | 在控制已觀測變數後，缺失與未觀測值無關 | 可利用其他已觀測欄位進行插補，仍須評估模型假設 |
| MNAR：非隨機缺失 | 缺失仍與未觀測值相關，例如高所得者較不願填所得 | 單純刪除或插補可能有偏誤；缺失指示欄可提供訊號，但不能單獨消除偏誤，須做敏感度分析 |
缺失處理的實務判準

| 缺失比例 | 建議處理 |
| --- | --- |
| < 5% | 可直接刪除該列，或簡單填補（平均／中位數／眾數） |
| 5–50% | 使用模型化填補（如 MICE、KNN）或加入缺失指示變數 |
| > 50% | 考慮整欄捨棄，或將「是否缺失」本身當成特徵 |

**經驗法則，非官方標準。** 處置前應先判斷 MCAR／MAR／MNAR、業務價值及偏誤風險；例如「是否填手機號碼」本身可能有預測資訊，但不能直接推定未填者一定是低黏著度客戶。
鐵律：插補的統計量必須只從訓練集計算，否則造成資料洩漏。

#### 4.1.3 ETL與 ELT
核心必考
| 比較 | ETL（先轉換再載入） | ELT（先載入再轉換） |
| --- | --- | --- |
| 流程 | 擷取 → 轉換 → 載入 | 擷取 → 載入 → 轉換 |
| 適用 | 結構明確、需嚴格治理的資料倉儲 | 善用儲存與運算資源、保留原始資料以利回溯 |

#### 4.1.4 考點補丁：類別編碼（Label Encoding 與 One-Hot）
核心必考

- **定義**：
  - **Label Encoding（標籤編碼）**：把每個類別映射為一個整數（紅=0、綠=1、藍=2）。
  - **One-Hot Encoding（獨熱編碼）**：每個類別一個二元欄位，只有所屬類別為 1，其餘為 0。
- **核心陷阱（本補丁的重點）**：**Label Encoding 會對無序類別引入不存在的順序關係。** 若把「臺北=0、臺中=1、高雄=2」直接餵給線性模型或神經網路，模型會算出「高雄 − 臺中 ≈ 臺中 − 臺北」這種無意義的加減，也會把「高雄」當成「比臺北大」。**只有當類別本身有大小順序時（如低／中／高、年級），Label Encoding 才恰當。**
- **一句判斷規則**：題幹出現「無序的類別特徵」「線性模型或神經網路」→ 用 **One-Hot**；出現「有序類別（等級）」→ 可用 Label Encoding 或有序編碼；出現「樹模型」→ Label Encoding 通常可接受（樹只做大小比較，不假設等距）。
- **One-Hot 的代價與替代**：
  - **維度爆炸**：高基數類別（如郵遞區號、商品 ID）會產生數千欄，須改用 **目標編碼（Target Encoding）**、**頻率編碼**或**嵌入（Embedding）**。
  - **共線性**：One-Hot 的 k 個欄位加總恆為 1，對線性模型會造成完全共線性；可用 `drop='first'` 去掉一欄。
- **必須避免的錯誤**：**在切分資料之前對全資料做目標編碼**，會把測試集標籤洩漏進訓練（見第 8 章資料洩漏）。
- **對照表**：

  | 編碼 | 適用類別 | 適用模型 | 主要風險 |
  |---|---|---|---|
  | Label Encoding | 有序 | 樹模型、有序類別 | 無序類別引入假順序 |
  | One-Hot | 無序、低基數 | 線性、神經網路 | 維度爆炸、共線性 |
  | Target Encoding | 無序、高基數 | 樹模型 | 目標洩漏 |
  | Embedding | 無序、極高基數 | 神經網路 | 需大量資料學習 |

- **依模型分別編碼**：同一份資料交給不同模型時，編碼可以不同。線性模型（如羅吉斯迴歸）：有序類別用**有序編碼（Ordinal Encoding）**，無序類別用 One-Hot 並 `drop='first'`。樹模型：有序類別用有序編碼；無序類別可用框架的**原生類別支援**（如 XGBoost 設 `enable_categorical=True`、LightGBM 的 categorical feature），不必展開成大量 One-Hot 欄。
- **不能改編碼時換模型**：若規定類別必須維持 1、2、3 的整數，線性模型仍會把它當等距數值；改用**樹模型**（決策樹、隨機森林、梯度提升）可降低這種誤解，因為樹只做「≤ 門檻」的切分，不會把 3 解讀為 1 的三倍。
- **對應題號**：114-2 L22 Q05（正解 B）、114-2 L22 Q17（正解 B，題幹＋正解）、115-1 L22 Q11（正解 C）、115-1 L22 Q42（正解 D）。

#### 4.1.5 考點補丁：醫療時序感測資料的清理
核心必考

- **定義**：病床監測、穿戴裝置等資料有四個共通問題：**連續缺失**、**感測器漂移**（讀值隨使用時間系統性偏移）、**標註時間誤差**、**個體基準差異**（每個人的正常值不同）。
- **一句判斷規則**：一個好方案必須**四個問題都處理，而且驗證不洩漏**。任何選項只要出現「隨機切分讓同一人同時進訓練與測試」或「以 Accuracy 評估極不平衡資料」，就可以先排除。
- **對照表**：

  | 問題 | 建議處理 | 不當處理 |
  |---|---|---|
  | 短時間連續缺失 | 前向填補（設上限）＋加入**缺失指示欄** | 以全體平均填補，抹掉時間結構 |
  | 感測器漂移 | 以**滾動中位數**等基準線校正 | 只做 Z-score 標準化（無法去除隨時間變化的偏移） |
  | 標註時間誤差 | 視為標註雜訊，排除或軟化不確定區間 | 任意擴大標註區間 |
  | 個體基準差異 | 以個人基準線做相對化 | 忽略個體差異直接建模 |
  | 驗證方式 | **依病患分組**切分（GroupKFold） | 逐筆隨機切分 |
  | 評估指標 | PR-AUC、Recall | Accuracy |

- **易混點**：
  - 同一病患的相鄰紀錄高度相關；逐筆隨機切分會讓模型「認得這個人」，測試分數虛高，這也是資料洩漏。
  - 加缺失指示欄的理由是「缺失本身可能有意義」（例如病況惡化時拔除感測器），但它不會自動消除偏誤。
- **對應題號**：115-1 L22 Q17（正解 D）。

#### 4.1.6 考點補丁：從資料層面緩解過擬合
核心必考

- **定義**：過擬合是模型記住了訓練樣本的細節與雜訊，訓練分數高、驗證分數低。不改模型架構時，資料層面的解法都是在**增加訓練資料的有效多樣性**或**去除錯誤訊號**。
- **一句判斷規則**：能讓模型「每次看到不一樣的樣本」的做法有幫助；讓模型「反覆看到完全相同的樣本」的做法沒有幫助，甚至會惡化。
- **對照表**：

  | 做法 | 效果 |
  |---|---|
  | 資料增強（訓練時動態隨機翻轉、裁切、調色） | 有效：每個 epoch 樣本都不同 |
  | 收集更多不同場景的資料 | 有效：擴大分布涵蓋 |
  | 清除標註錯誤、品質不佳的樣本 | 有效：減少模型去記憶雜訊 |
  | 先把特徵算好並快取，反覆使用同一份 | 無效：失去隨機性，只是加快訓練 |
  | 對少數類做隨機複製（過採樣） | 可能惡化：重複樣本更容易被記住 |

- **易混點**：快取的目的是提升吞吐量，是**效率**手段，不是**泛化**手段。若快取的是增強後的固定版本，等於把動態增強變回靜態資料，會削弱增強的效果。
- **對應題號**：115-1 L22 Q15（正解 C）。

### 4.2 程式判讀重點
核心必考
清理操作的列數變化與就地修改

```python
df.isna().sum()#->Series（各欄缺失數）
df.dropna()#預設how='any'：任一欄為NaN即刪整列
df.dropna(subset=['a'])#僅依a欄判斷
df.drop_duplicates()#預設比對「所有欄位」，需整列相同才算重複
df.drop_duplicates(subset='id')#依id去重
df= df.dropna(inplace=True)#危險：inplace回傳None->df變成None
```

三個必考細節：(1) dropna() 預設 how='any'，只要有一欄缺失就刪整列，殺傷力極大；(2)
drop_duplicates()預設比對全部欄位，只有整列完全相同才算重複，要依 id去重須指定subset；(3)
inplace=True就地修改並回傳None，寫成df = df.xxx(inplace=True)會讓df變成None。

#### 4.2.1 考點補丁：Python 可變預設引數
核心必考

- **定義**：Python 函式的預設引數在**定義函式時只建立一次**。若預設值是可變物件（`list`、`dict`、`set`），之後每次呼叫都共用**同一個物件**，前一次呼叫留下的修改會帶到下一次。
- **一句判斷規則**：看到 `def f(..., x=[])` 或 `x={}`，且函式內對 `x` 做 `append`、`update` 或把它塞進回傳資料 → 第二次呼叫時，`x` 已經帶著第一次的內容。
- **程式範例**：

  ```python
  def fill(row, default=[]):
      default.append("seen")
      row.setdefault("notes", default)
      return row

  a = fill({})   # a["notes"] == ["seen"]
  b = fill({})   # b["notes"] == ["seen", "seen"]，而且 a["notes"] 也變了
  ```

- **正確寫法**：預設值用 `None`，在函式內建立新物件。

  ```python
  def fill(row, default=None):
      if default is None:
          default = []
      default.append("seen")
      row.setdefault("notes", default)
      return row
  ```

- **易混點**：
  - 這不是 KeyError。`setdefault` 在鍵不存在時會自動補上，不會拋錯。
  - 兩筆資料共用同一個 list，是**同一物件的兩個參照**；改其中一筆，另一筆也跟著變。資料管線中這會造成難以追查的交叉汙染。
  - 不可變的預設值（數字、字串、`None`、`tuple`）沒有這個問題。
- **對應題號**：115-1 L22 Q39（正解 C，程式圖）。

### 4.3 常見陷阱與錯誤觀念
• 以 0填補數值型缺值。0通常是合法值，模型會把「沒填」誤解為「數值為零」。
• 在切分前插補。統計量取自含測試集的全部資料，屬資料洩漏。
• 把dropna()當萬用。預設會因單一欄缺失而刪掉整列，可能一次砍掉七成資料。
• 把 MNAR當 MCAR處理。高所得者不填所得，刪除後樣本系統性偏低。
• 誤用inplace。回傳None的經典錯誤。
• 只清理不記錄。清理決策（刪了哪些列、插補了什麼）必須留存，否則無法追溯。

#### 模擬題 SIM-L22201-001

模擬題 SIM-L22201-001 ｜ 程式判讀 ｜ 難度：中級 ｜ 對應 L22201
df有 1,000列、5欄。其中age欄有 40筆 NaN、email欄有 300筆 NaN，其餘欄無缺失，且兩欄
缺失位置不重疊。執行df2 = df.dropna()後，df2的列數為何？
(A) 1000
(B) 960
(C) 700
(D) 660
答案與逐項解析
答案：D
dropna()預設how='any'：任一欄為 NaN即刪除整列。
缺失位置不重疊，故受影響列數 = 40+300 = 340。1000−340 = 660。
(A) ×未考慮刪除。
(B) ×只算了age的 40筆。
(C) ×只算了email的 300筆。
(D)✓正解。
干擾項設計理由：(B)(C)針對「只想到自己關心的那一欄」的疏漏。
延伸考點：若缺失位置完全重疊，則僅刪 300列，結果為 700。題幹是否說明重疊情形是關鍵資訊。
若只想依age判斷應寫df.dropna(subset=['age'])；若要「全部欄皆缺失才刪」則用how='all'。本例
email缺失率達 30%，實務上不應直接刪列，而應插補並新增缺失指示欄。

#### 模擬題 SIM-L22201-002

模擬題 SIM-L22201-002 ｜ 程式判讀 ｜ 難度：中級 ｜ 對應 L22201
下列程式意圖「依customer_id去除重複客戶」，但結果不如預期。問題為何？
```python
df_clean= df.drop_duplicates()
```

(A)沒有問題，drop_duplicates()預設即依第一欄去重
(B)drop_duplicates()預設比對所有欄位，只有整列完全相同才算重複；同一客戶若其他欄位有任
何差異就不會被去除，應指定subset='customer_id'
(C)應改用df.dropna()
(D)應加上inplace=True才會生效
答案與逐項解析
答案：B
(A) ×預設不是依第一欄，而是比對全部欄位。
(B)✓正解。同一customer_id若在交易日期、金額等欄位有差異，整列就不相同，不會被視為重
複。正確寫法為df.drop_duplicates(subset='customer_id', keep='first')。
(C) ×dropna()處理的是缺失值，與重複無關。
(D) ×inplace只影響是否就地修改，不改變去重的比對邏輯；且本例已將結果指派給新變數，加
inplace=True反而會讓df_clean變成None。
干擾項設計理由：(D)是實務上很常見的「加參數試試看」反應，正好踩中inplace回傳None的陷
阱。
延伸考點：keep參數可為'first'（保留首筆）、'last'（保留末筆）、False（重複的全部刪除）。若要
保留每位客戶最新一筆，須先sort_values再以keep='last'去重。

#### 模擬題 SIM-L22201-003

模擬題 SIM-L22201-003 ｜ 情境題 ｜ 難度：中級 ｜ 對應 L22201
某問卷資料中，「月收入」欄位缺失率達 28%，且經分析發現高收入受訪者傾向不填此欄。下列處置
何者最為適當？
(A)以全體平均收入填補缺失值，因平均數利用了全部可得資訊
(B)此屬 MNAR（缺失與未觀測值本身相關），簡單插補會系統性低估收入；應保留缺失指示欄、採
用適當的插補方法並於報告中揭露此偏誤風險
(C)直接刪除所有缺失列，即可得到乾淨資料
(D)以 0填補，因為未填答代表沒有收入
答案與逐項解析
答案：B
(A) ×以觀測到的平均填補，而觀測值本身已偏向中低收入，會使整體分布更向中低集中，偏誤加
劇。
(B)✓正解。「高收入者傾向不填」正是 MNAR的定義——缺失與該欄未觀測到的值本身相關。此時
任何僅依觀測值推估的方法都會低估，故須保留指示欄、選用適當方法並明確揭露偏誤風險。
(C) ×刪除缺失列會直接移除高收入群體，樣本代表性嚴重受損。
(D) ×「未填答」與「收入為 0」是完全不同的事，此填補會製造大量假的零收入樣本。
干擾項設計理由：(D)是最常見的懶人作法，也是本章反覆強調的錯誤。
延伸考點：三種缺失機制的判別關鍵——與任何變數都無關為 MCAR；與其他已觀測變數有關為
MAR；與該欄自身未觀測值有關為 MNAR。MNAR無法僅靠資料本身修正，須依賴領域知識或額
外的抽樣設計。

#### 模擬題 SIM-L22201-004

模擬題 SIM-L22201-004 ｜ 觀念題 ｜ 難度：基礎 ｜ 對應 L22201
某企業建置雲端資料平台，希望先將各來源系統的原始資料完整落地保存，之後再依不同分析需求
撰寫轉換邏輯，且允許重跑。此架構最接近下列何者？
(A) ETL，因為資料最終仍會被轉換
(B) ELT，先載入原始資料再於平台內轉換，保留原始資料以利回溯與多次重跑
(C)兩者皆非，此為串流處理架構
(D)兩者無實質差異，僅是名稱不同
答案與逐項解析
答案：B
(A) × ETL是在載入前完成轉換，進倉的已是清洗後資料，不保留原始樣態。
(B)✓正解。「先完整落地、之後再依需求轉換、允許重跑」正是 ELT的核心特徵，也是雲端資料
湖與湖倉架構的典型作法。
(C) ×題幹未提及連續事件流與低延遲需求。
(D) ×轉換發生的位置與時點不同，直接影響治理方式、成本結構與可回溯性。
延伸考點：ELT的代價是治理難度——原始資料若無中繼資料、無存取控制、無生命週期管理，資
料湖會迅速退化為資料沼澤。此議題於 Chapter 5完整處理。
