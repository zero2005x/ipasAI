### 10.1 核心概念與技術原理

<!-- pdf-page 88 -->
#### 10.1.1 5V對機器學習的具體衝擊
核心必考
| 特性 | 對 ML 的挑戰 | 可評估的技術 |
|---|---|---|
| Volume（量） | 資料難以載入單機或訓練時間太長 | 分散式訓練、增量學習、抽樣 |
| Velocity（速度） | 特徵須即時更新，模型可能過時 | 串流特徵、線上學習、線上線下一致的特徵存放區 |
| Variety（多樣性） | 結構化與非結構化資料並存 | 多模態建模、湖倉架構、綱要管理 |
| Veracity（可信度） | 標籤雜訊、感測異常、重複紀錄 | 資料驗證管線、穩健損失、主動學習 |
| Value（價值） | 大量資料中有用訊號稀少 | 特徵選擇、領域知識、因果分析設計 |
資料多不等於效果好
在訊號稀疏的情況下，只增加樣本量未必能改善效能；也應檢查特徵是否有用、標籤品質及學習曲線。若訓練與驗證誤差都高且接近，可優先檢查欠擬合、特徵不足或標籤問題，不能只憑這個現象斷定更多資料完全無用。

<!-- pdf-page 89 -->
#### 10.1.2 分散式訓練的兩種切法
官方補充
• 資料平行：每個節點放一份完整模型、處理不同批資料，再同步梯度。最常用，適合模型放得進單機
的情況。
• 模型平行：模型太大放不進單機，把模型不同層或不同部分切到不同節點。通訊成本高。

<!-- pdf-page 89 -->
#### 10.1.3 維度詛咒
核心必考
特徵數增加時，資料在高維空間中變得極度稀疏，任兩點的距離趨於相近，使基於距離的方法
（KNN、K-Means）失效，且達到相同資料密度所需的樣本量呈指數成長。
緩解手段：特徵選擇（過濾式／包裹式／嵌入式）、降維（PCA）、正則化、以及改用對高維較穩健的
模型（樹模型、加強正則化的線性模型）。

#### 10.1.4 考點補丁：批次大小、梯度雜訊與泛化
核心必考

- **觀察**：在相同資料、模型與訓練設定下，大批次通常提高硬體吞吐且使單步梯度估計較穩定；小批次的梯度雜訊較大，可能有助於探索不同的參數區域。因此題幹若描述「大批次訓練更快但測試表現較差」，可先從梯度雜訊及更新次數的差異解釋。
- **不可誤解為定律**：大批次不必然泛化較差。學習率排程、訓練步數、正則化和硬體利用方式都會改變結果；應在公平的訓練預算與驗證設計下比較。[大批次泛化研究](https://proceedings.neurips.cc/paper/2017/file/a5e0ff62be0b08456fc7f1e88812af3d-Paper.pdf)展示調整訓練方式可縮小泛化差距。
- **對應題號**：115-1 L22 Q30（正解 B）。

#### 10.1.5 學習指引補充：大規模訓練的四項技術
官方補充

- **混合精度訓練**：以 FP16 或 BF16 進行大部分運算，另保留 FP32 的主權重；可減少記憶體並加速運算。FP16 範圍較窄，常搭配損失縮放（loss scaling）避免梯度下溢。
- **梯度累積**：連續算數個小批次的梯度並累加，再更新一次參數，等效於較大的批次，適合 GPU 記憶體放不下大批次時使用。
- **檢查點（checkpoint）**：定期儲存模型權重與優化器狀態，訓練中斷時可從最近的檢查點接續。另有「啟動值重算（activation checkpointing）」以重算換取記憶體，兩者名稱相近但用途不同。
- **持續學習**：模型隨新資料持續更新；主要風險是**災難性遺忘**，常見對策是重播部分舊資料或加入限制舊參數大幅變動的正則化。
- **一句判斷規則**：「記憶體不夠放大批次」→ 梯度累積或混合精度；「訓練跑數天怕中斷」→ 檢查點；「新資料學會了、舊任務卻變差」→ 災難性遺忘。
- **指引頁碼**：學習指引科目二 6-6、6-10、6-11。

### 10.2 程式判讀重點
核心必考
形狀與聚合軸
```python
X.shape#(1000,20)->1000列樣本、20個特徵
X.mean(axis=0)#沿「列」方向壓縮->每個特徵的平均，形狀(20,)
X.mean(axis=1)#沿「欄」方向壓縮->每個樣本的平均，形狀(1000,)
X- X.mean(axis=0)#廣播：(1000,20)-(20,)->逐特徵中心化，合法
# X- X.mean(axis=1)#錯誤：(1000,20)-(1000,)形狀不相容，需 reshape(-1,1)
```

必考：axis=0是「沿著第 0軸做聚合」，結果會消掉列而留下欄——即得到各特徵的統計量。這是特
徵標準化最常用的軸。廣播規則要求尾端維度相容，axis=1的結果需reshape(‑1,1)才能相減。

### 10.3 常見陷阱與錯誤觀念
• 以為資料量越大效果一定越好。訊號稀疏時邊際貢獻迅速遞減。
• 在高維空間用距離型演算法。維度詛咒下距離失去鑑別力。
• 混淆axis=0與axis=1。特徵標準化用axis=0。
• 忽略 Veracity。標籤雜訊會設下效能天花板，再多資料也突破不了。
• 把分散式訓練當成萬靈丹。通訊成本可能抵銷平行帶來的加速。

#### 模擬題 SIM-L22401-001

模擬題 SIM-L22401-001 ｜ 程式判讀 ｜ 難度：中級 ｜ 對應 L22401
X為形狀(1000, 20)的 NumPy陣列（1000個樣本、20個特徵）。若欲對每個特徵做中心化，下列
何者正確？
(A)X‑ X.mean(axis=1)
(B)X‑ X.mean(axis=0)
(C)X ‑ X.mean()
(D)X.mean(axis=0) ‑ X
答案與逐項解析
答案：B
(A) ×axis=1得到形狀(1000,)，是每個樣本的平均；與(1000,20)相減會因廣播規則不相容而報錯。
(B)✓正解。axis=0沿列方向聚合，得到形狀(20,)的各特徵平均；廣播後與每一列相減，達成逐
特徵中心化。
(C) ×不指定軸會得到全域單一平均值（純量），所有特徵減去同一個數，不是逐特徵中心化。
(D) ×順序顛倒，得到的是負的中心化結果。
延伸考點：記憶法——axis=0消掉列留下欄，因此得到「每欄（每個特徵）」的統計量；axis=1消掉
欄留下列，得到「每列（每個樣本）」的統計量。在本題「列為樣本、欄為特徵」的矩陣排法下，逐特徵中心化或標準化應沿 axis=0 求各欄統計量；PCA 則使用中心化後的特徵矩陣，並非另有一個固定的 `axis` 參數。若真要用
axis=1的結果相減，須先reshape(‑1,1)。

#### 模擬題 SIM-L22401-002

模擬題 SIM-L22401-002 ｜ 診斷題 ｜ 難度：中級 ｜ 對應 L22401
某團隊的模型在 100萬筆資料上訓練誤差與驗證誤差皆偏高且兩者接近。主管建議「再蒐集 500萬
筆資料」。下列評論何者最為適當？
(A)建議正確，資料量是模型效能最主要的決定因素
(B)兩條誤差曲線皆高且已收斂，屬高偏差（欠擬合）；增加資料量幫助有限，應改用更複雜的模型
或增加更有資訊量的特徵
(C)應直接增加特徵數量至數千維，維度越高模型表達力越強
(D)應改用距離型演算法以充分利用大量資料
答案與逐項解析
答案：B
(A) ×資料量的邊際貢獻取決於目前的瓶頸是偏差還是變異。
(B)✓正解。訓練與驗證誤差皆高且接近是高偏差的典型徵狀——模型連訓練資料都學不好，再餵更
多同類資料仍學不好。正確方向是提高模型複雜度、增加特徵，或減少正則化強度。
(C) ×盲目增加維度會觸發維度詛咒：資料稀疏化、距離失效、所需樣本量指數成長，且過擬合風
險升高。應增加的是有資訊量的特徵而非數量。
(D) ×距離型演算法在高維與大規模資料上的表現與效率都更差。
延伸考點：學習曲線診斷法——兩線都高且收斂→高偏差，加資料無用；兩線間距大且未收斂→
高變異，加資料有用。這個判斷直接決定「花錢買資料」還是「花時間換模型」，是規劃師的關鍵決
策。此議題於 L23101有完整處理。

#### 模擬題 SIM-L22401-003

模擬題 SIM-L22401-003 ｜ 觀念與治理題 ｜ 難度：中級 ｜ 對應 L22401
某都會區智慧交通監控中心每日匯流數億筆路側感測器與行車即時車速數據（具有極高的 Volume 與 Velocity 特徵）。然而，因戶外設備受風雨侵蝕及傳輸封包丟失，資料中夾雜約 8% 的量測極值、時間戳記錯亂與錯誤標籤。分析團隊主張「在大數據時代，只要資料量足夠龐大，模型就能自行克服所有瑕疵，故無須進行耗時的前置資料治理」。下列專業評估何者最為正確？
(A)團隊主張正確，深度神經網路在海量資料支援下，具有數學定理保證可完全免疫於任何標籤雜訊
(B)團隊主張有嚴重誤導；大數據 5V 中的 Veracity（真實性與品質）是模型效能的底層基石。標籤雜訊與資料污染會直接設定模型泛化能力的天花板，盲目依賴未經治理的海量髒資料只會導致訓練過程震盪與擬合錯誤訊號
(C)Velocity 過快會導致所有優化演算法的學習率強制失效
(D)感測器資料量大時，應改用無監督分群，因分群演算法在數學上保證完全不依賴資料品質
答案與逐項解析
答案：B
(A) ×海量資料不能自動抵銷系統性標籤錯誤；若訓練資料本身包含錯誤標籤，模型會學會擬合錯誤規律，並在推論時輸出錯誤結果。
(B)✓正解。大數據環境下「Garbage In, Garbage Out」的鐵律依然完全成立。Veracity 構面涉及資料的準確性、真實性與可信度；標籤雜訊不僅降低收斂速度，更會嚴重損害離線與線上指標的真實性。投入前置資料清洗、時間戳對齊與品質監控，是海量數據應用成功的前提。
(C) ×資料抵達速度（Velocity）主要影響串流管線與快取架構，與批次模型訓練時的學習率參數無直接因果關係。
(D) ×無監督分群（如 K-Means、DBSCAN）對離群值與雜訊更為敏感，同樣極度依賴高品質資料。
干擾項設計理由：(A)直指「資料多就不用管品質」的海量數據迷思；(D)將無監督學習誤當成資料容錯萬靈丹。
延伸考點：大數據 5V 治理架構：Volume（透過分散式儲存與分區應對）、Velocity（透過串流處理與視窗聚合應對）、Variety（透過資料湖與多模態融合應對）、Veracity（透過資料品質稽核與清洗管線應對）、Value（透過場景轉譯與效益量化實現）。

#### 模擬題 SIM-L22401-004

模擬題 SIM-L22401-004 ｜ 分散式架構題 ｜ 難度：中級 ｜ 對應 L22401
某電腦視覺團隊擬訓練一個卷積神經網路分類模型。該模型權重檔案大小約為 300MB，單張伺服器級 GPU（顯存 24GB）即可完整載入模型參數、啟動值與優化器狀態；但訓練集包含高達 8,000 萬張高解析度影像，以單 GPU 串行訓練估計耗時將超過 40 天。為縮短訓練週期至數天內，團隊向雲端租用包含 16 張 GPU 的運算叢集。最適當的分散式平行訓練策略為何？
(A)模型平行（Model Parallelism）：將 300MB 的模型各層網路依序拆分部署在 16 張不同的 GPU 上，每張 GPU 僅運算神經網路的少數幾層
(B)資料平行（Data Parallelism）：在 16 張 GPU 上各自複製一份完整的模型副本，將 8,000 萬張影像分批分配給各 GPU 同時運算，反向傳播後同步聚合（All-Reduce）梯度並更新權重
(C)停用所有 GPU 加速，改在單一節點 CPU 上逐筆讀取影像以降低 GPU 節點間的網路通訊負擔
(D)將訓練集影像解析度隨機縮小為原本的 1%，以避免使用任何平行計算架構
答案與逐項解析
答案：B
(A) ×模型平行（Model Parallelism）專用於「模型本身過大、單張 GPU 顯存無法容納」的情境（如數百億參數的大型語言模型）。本題模型僅 300MB，單卡顯存 24GB 綽綽有餘，若硬採模型平行會造成嚴重的層間管線等待與通訊瓶頸，得不償失。
(B)✓正解。當「單卡顯存足以容納完整模型，但資料量極為龐大」時，資料平行（Data Parallelism）為業界最成熟且加速比最高的標準方案。每張卡載入相同模型、平行計算不同數據批次的梯度，再透過高速通訊（如 NCCL Ring All-Reduce）平均梯度更新模型，能近乎線性地縮短訓練時間。
(C) ×CPU 算力遠落後於 GPU，會使訓練時間由數十天延長至數年。
(D) ×粗暴縮小影像會丟失絕大部分視覺特徵與細節，使模型失去辨識鑑別力。
干擾項設計理由：(A)是分散式計算最核心的選型考點，測試考生是否清楚資料平行與模型平行的適用分界。
延伸考點：資料平行訓練時，若加大全局批次大小（Global Batch Size = 單卡 Batch $\times$ 卡數），實務上常搭配學習率線性預熱（Learning Rate Warmup）與線性縮放原則，以維持隨機梯度下降的泛化表現。
