# iPAS 中級教科書 v0.3 排版修正計畫（交付執行 agent）

> 本文件是給執行排版修正的 AI agent 的完整工作指示。請從頭讀完再動手，並依階段順序執行；每個階段完成後自行驗收、commit，再進下一階段。

## 0. 背景與目標

三冊書稿（`book/L21|L22|L23/v0.3/*.md`，另有三冊共用內容在 `shared/book/`）由 `tools/build_pdf.py` 轉成 HTML，再以 Chrome headless 輸出 A4 PDF。**內容已完成查核**（見 `audit/v0.3_續校正查核_1150925.md` 的 C01–C51），本輪**只改排版**，不改內容。

使用者對目前排版的四項不滿（全部要修）：

1. **句子被切成碎段**：原稿是由 PDF 擷取而來，保留了硬換行；編譯器把每一行輸出為一個 `<p>`，全書約 1,600 處句子中途斷開（例：「……網頁停留」／「時間。」成為兩段）。
2. **模擬題版型**：題型列重複標題、選項沒有縮排、「答案與逐項解析」緊貼題目後面。
3. **表格欄寬與折行**：欄寬自動分配，短欄被擠成直排（「科目一」一字一行），`ERR-1150410-01`、`OFFICIAL-…` 等 ID 被切成多行（附錄 B 最嚴重）。
4. **整體像報告不像課本**：分層標籤、考點補丁、易混點、陷阱都只是一般文字；章首沒有設計；前頁各篇標題只是一般段落。

使用者已決定：

| 項目 | 決定 |
|---|---|
| 模擬題答案位置 | **集中到各章章末**「模擬題解答與解析」（題組亦同） |
| 視覺風格 | **輕度色彩課本風**：一個主色加淡底色塊；黑白列印仍須可讀 |
| 頁面尺寸 | **維持 A4** |
| 執行方式 | **單一 agent 分階段依序執行**，每階段驗收後再進下一階段 |
| 版本控制 | 在新分支 `layout/v0.3` 工作，**每階段一個 commit**；**不得合併回 master**，由使用者驗收後合併 |
| PDF 標示 | 維持「校訂稿」（`build_pdf.py <VOL> --draft`，輸出 `build/<VOL>/<VOL>_v0.3_校訂稿.pdf`） |

## 1. 鐵則（違反即視為失敗）

1. **不改內容**：不得增刪、改寫任何文字、數字、公式、選項或答案。允許的原稿變更只有：
   - 合併被硬換行切斷的行（刪除換行字元）；
   - 在段落之間補空行；
   - 為程式識別字加上反引號 `` ` ``；
   - 把前頁各篇的首行標題改成 Markdown 標題；
   - 把框線標籤行改成提示框語法（第 3.5 節）；
   - 還原第 3.6 節列出的 1 張壓平表格。
2. **每次改原稿都要通過文字完整性守衛**（第 2 節的 `tools/check_text_integrity.py`）：每個檔案去除空白、反引號與提示框標記後的字元序列，必須與改動前**完全相同**。
3. **答案搬到章末只能在編譯階段做**（`build_pdf.py`），**不得搬動原稿**。原稿維持「題目後緊接答案」的寫法，方便日後維護；`recount_stats.py`、`check_book.py` 依賴這個結構。
4. 不得改動下列結構，否則檢查工具會失效：
   - 章節識別卡表格列（`| 本版題數 | …{{stats.…}}… |` 等佔位符）；
   - 公告試題索引列 `| OFFICIAL-… |`、指引練習題索引列 `| GUIDE-… |`；
   - 小節標題格式 `#### x.y.z 標題`，以及其下一行的分層標籤（`核心必考`／`官方補充`／`產業延伸`）；
   - 模擬題標題 `#### 模擬題 SIM-…`、題型列 `模擬題 SIM-… ｜ 題型 ｜ 難度：… ｜ 對應 …`、`答案與逐項解析`、`答案：X`；
   - 題組標題 `#### 題組 SET-…`；
   - `<!-- include: … -->`、`<!-- pdf-page N -->` 註解。
5. 不得執行 `tools/make_front_matter.py`、`tools/make_v03.py`（一次性產生器，會覆寫共用檔）。
6. `tmp/`、`尚未整理/`（官方原卷與學習指引 PDF）不得提交。

**階段 0 須新增**：`tools/check_text_integrity.py`

- 用法一：`python tools/check_text_integrity.py snapshot`
  - 把每個 `book/**/v0.3/*.md` 與 `shared/book/**/*.md` 做正規化，再存成 `tmp/integrity_baseline.json`（檔名 → SHA-256 與長度），同時保存正規化後全文以便指出差異位置。正規化要去除：
    - 所有空白與換行；
    - 反引號；
    - `:::類型` 與單獨的 `:::` 標記（標籤文字保留）；
    - 行首的 Markdown 標題井號；
    - 表格的 `|` 與分隔列（`|---|---|`）。
- 用法二：`python tools/check_text_integrity.py verify`
  - 用同樣方式重算並比對，有任何不同就印出檔名與第一個差異位置，並以 exit 1 結束。
- 這些剝除規則正好涵蓋第 1 節允許的原稿變更（合併換行、反引號、前頁標題、提示框、表格重建），讓合法變更不會誤報，其他任何改字都會被抓到。

## 3. 階段一：原稿結構修復（只動 Markdown）

開始前先執行：建分支 `git switch -c layout/v0.3`，然後 `python tools/check_text_integrity.py snapshot`。

執行順序：3.6 → 3.5（先標出提示框範圍）→ 3.1 → 3.2 → 3.3 → 3.4。每一小節做完都跑一次 `check_text_integrity.py verify`。

### 3.1 合併硬換行（最高優先）

寫 `tools/unwrap_lines.py`，對 `book/**/v0.3/*.md` 與 `shared/book/**/*.md` 處理：

- **合併條件**：相鄰兩行 `a`、`b` 都是一般內文行，且符合下列任一條件時，把 `b` 接到 `a` 後面（直接相接，不加空格；若 `a` 以英數字結尾、`b` 以英數字開頭，則補一個半形空格）：
  - `a` 不以句末標點（`。！？：；」）)`）結尾；或
  - `a` 的顯示寬度（全形字算 2）達到原 PDF 滿行寬度的約 85%（請先抽樣量出滿行寬度，約 88–96 半形單位）。
- **不得合併**的行：
  - 空行、標題、表格列、清單項（`- `、`* `、`1.`，以及擷取稿常見、後面不接空格的 `•`，例如 `•混淆「複雜度低」…`）、引用 `>`、程式區塊內的行、`<!-- -->` 註解；
  - 分層標籤行（`核心必考`、`官方補充`、`產業延伸`、`版本敏感`）；
  - 選項行 `(A)`～`(D)` 的**開頭**。選項本身被切斷的續行要合併回該選項。
  - 模擬題固定標記：`答案與逐項解析`、`答案：X`、`干擾項設計理由：`、`延伸考點：`；這些行的**開頭**都不得接到前一行，但它們自己的續行要合併回來。
  - 提示框的 `:::類型 標籤` 開頭行與 `:::` 結尾行（第 3.5 節已先標好），以及尚未改成提示框的標籤行（`本章命題密度`、`著作權處理與使用方式`、`來源與稽核紀錄` 等）。
- **特別注意**：「•」開頭的清單在擷取稿中常見，其續行也要合併回該清單項。
- 合併後在原本分屬不同段落的行之間補一個空行（若兩行都以句末標點結束，且下一行不是續行，視為兩段）。
- 執行後：
  - `python tools/check_text_integrity.py verify` 必須通過；
  - 依附錄 A 的規則重新偵測，殘留須 ≤ 50 處，且逐一列出原因（例如本來就是兩句短句）。
- 範例（L21 `ch01.md` 第 270–271 行）：`•混淆「複雜度低」與「可並行」。…比 RNN高；它贏` 與 `在可並行而非省算力。…` 應合併成同一個清單項。

### 3.2 前頁標題

- `shared/book/front/*.md` 與 `book/<VOL>/v0.3/front/*.md` 的第一行是篇名，目前只是一般文字。
- 改成 `## 篇名`，讓它成為標題，進入第 4.3 節的章首樣式。
- 注意：`check_book.py` 以 `^## 第\s*\d+\s*章` 辨識章標題，前頁的 `##` 不會被誤認，但仍要重跑確認。

### 3.3 行內程式碼標記

- 目前 L21 全冊只有 14 處反引號，大量程式識別字用內文字型排版，中英文擠在一起（例：「依customer_id去除」）。
- 寫 `tools/mark_inline_code.py`，只在內文行（非程式區塊、非表格標題列、非標題）中，把下列候選包上反引號：
  - 含底線的識別字（`customer_id`、`n_components`）；
  - 含括號的呼叫（`drop_duplicates()`、`df['x'].mean()`）；
  - 點號方法鏈（`df.dropna`）；
  - `參數=值`（`inplace=True`、`ddof=1`）；
  - 已知 API 名（`fit_transform`、`train_test_split` 等）。
- 已在反引號內的不動；中文、一般英文單字（如 BERT、ROC）不動。
- **先輸出候選清單** `tmp/inline_code_candidates.tsv`（檔名、行號、原文片段、將標記的字串），人工抽查 50 筆無誤再套用。套用後執行 integrity 守衛（反引號會被剝除，應通過）。

### 3.4 分層標籤檢查

確認每個 `#### x.y.z` 與 `### x.2 程式判讀重點` 等標題的下一行若是分層標籤，中間沒有空行（`build_pdf` 依此判斷）。行尾殘留的「 版本敏感」「（產業延伸）」保持原樣，由編譯器處理成徽章（第 4.4 節）。

### 3.5 框線標籤改成提示框語法

- 原書 v0.2（`ori_book_pdf/*.pdf`）有灰底或框線的提示框，擷取後只剩一行標籤文字加上下方段落。全書約 100 處，扣除模擬題與樣板後的常見標籤：
  - 常見陷阱與錯誤觀念（14）、產業延伸（非官方核心考點）（5）、選型訊號（3）、最易混淆的一點、選型口訣、方向性必背、本章第一名考點、高頻誤述，以及各章獨有的標題式標籤。
- 定義語法（`md_to_html` 在第 4 階段支援）：

  ```
  :::trap 常見陷阱與錯誤觀念
  （原本的段落，一字不改）
  :::
  ```

  類型：`trap`（陷阱、誤述）、`key`（本章第一名考點、必背、方向性）、`tip`（選型訊號、口訣、判斷規則）、`ext`（產業延伸）、`note`（其他）。
- **提示框範圍的判定**：以 `pdftoppm` 渲染 v0.2 原書對應頁（頁碼可由原稿中的 `<!-- pdf-page N -->` 找到），看原框線包住哪幾段。若無法判定，只包標籤後的第一段。
- 輸出盤點表 `tmp/callout_inventory.tsv`（檔名、行號、標籤、類型、包含段數、判定依據）。
- 套用後 integrity 守衛必須通過（守衛會剝除 `:::類型` 與 `:::`，標籤文字保留）。

### 3.6 最後一張壓平表格

- L21 `ch01.md` 第 259–266 行（1.2.2 七項折衷檢查）的「面向／關鍵決策」表（7 列：成本、準確率、延遲、可解釋性、資安、隱私、維運）仍是壓平文字，每列以第一個空格分隔兩欄。

- 這張表必須在第 3.1 節合併硬換行**之前**處理，否則會被合併成一段。

## 4. 階段二：編譯器元件（只動 `tools/build_pdf.py`）

### 4.1 模擬題卡片

- 在 `md_to_html` 前加一個前處理，辨識 `#### 模擬題 SIM-…` 區塊。
- 題型列 `模擬題 SIM-… ｜ 情境題 ｜ 難度：中級 ｜ 對應 L21101` 改成標題下方的一排標籤（題型、難度、對應代碼），不再重複印 SIM 編號。
- 選項 `(A)`～`(D)` 輸出為選項清單：懸掛縮排、選項字母對齊、每個選項一個區塊。
- 題幹中的程式區塊照常輸出。
- 整張題目卡：淡底色、左側主色細條、`break-inside: avoid`；卡片過長時，允許在選項前分頁。
- 卡片右上角加小字「解答見本章末」。

### 4.2 答案移到章末

- 每個模擬題區塊從 `答案與逐項解析` 那一行起到區塊結束，是答案部分，從原位置移除。
- 答案部分依原順序收集，輸出在該章檔案最後，新增一節 `模擬題解答與解析`（h3、不編節號，避免與索引節號衝突）：
  - 每題一個小標題「SIM-L22201-002　答案：B」，下接逐項解析、干擾項設計理由、延伸考點。
  - 「答案：X」做成醒目徽章。
- **題組**：`#### 題組 SET-…` 的共用程式碼留在原處；解答區以「題組 SET-…」小標題分組，底下列各小題解析。
- 章末位置：放在整個章檔案內容之後（也就是「來源與稽核紀錄」之後）。
- 驗證：
  - 每章移走的答案數必須等於該章 `#### 模擬題` 數；
  - 輸出 HTML 中，`答案與逐項解析` 不得出現在任何模擬題卡片內。

### 4.3 章首與前頁

- 章檔案的 `## 第 N章 標題`：做成章首頁，大號章號、章名、主色色帶；每章從新頁開始（已有 `.chapter { break-before: page }`）。
- 前頁各篇的 `##`（第 3.2 節）用同一套較小的樣式。
- 章節識別卡表格：做成兩欄資訊卡（左欄淡底、粗體）。
- 「學習目標」：用編號清單樣式。
- 「考綱對位」：標籤行改成表格標題。

### 4.4 分層標籤與徽章

- 標題下一行的分層標籤不再單獨佔一行，改成標題右側的徽章：
  - 核心必考：主色實心；
  - 官方補充：主色外框；
  - 產業延伸：灰色外框；
  - 版本敏感：琥珀色。
- 內文中單獨一行或行尾的「版本敏感」「（產業延伸）」「**版本敏感**」，也轉成同樣的行內徽章。
- `recount_stats.py` 讀的是原稿，不受影響，不需修改。

### 4.5 表格

- 在 `md_to_html` 產生表格時計算每欄內容的顯示寬度（全形 2、半形 1），輸出 `<colgroup>` 指定欄寬：
  - 某欄所有儲存格最長 ≤ 12 單位時，設為剛好容納的寬度並 `white-space: nowrap`；
  - 其餘寬度依各欄平均長度的平方根比例分配；
  - 任一欄最小寬度不得小於 4 個全形字。
- 符合 `^(OFFICIAL|GUIDE|ERR|SIM|SET|GOV|IPAS)[-‑]` 的 ID 一律包 `<span class="nowrap">`；索引類表格字級降為 9pt。
- 表頭淡主色底、粗體；奇偶列淡色交錯；`thead` 跨頁重複（Chrome 在有 `<thead>` 時會自動重複）。
- 超過 15 列的表格移除 `page-break-inside: avoid`，改成 `tr { break-inside: avoid }`，避免大段留白。

### 4.6 提示框與特殊小節

- 支援第 3.5 節的 `:::類型 標題 … :::` 語法：輸出為提示框（圓角、淡底、左側色條、標題列帶圖示字元），`break-inside: avoid`。
- 依標題文字自動套用區塊樣式：
  - `#### … 考點補丁：…`：整節包成「考點補丁」框（主色左框）；
  - `#### … 學習指引補充：…`：「學習指引補充」框（藍灰）；
  - `（三冊共用模組）`：共用模組框。
  - 整節包框時要讓框可跨頁，不設 `break-inside: avoid`。
- `### x.y 常見陷阱與錯誤觀念`、`### x.y 政府指引與產業落地實務`：該節標題加對應色條。
